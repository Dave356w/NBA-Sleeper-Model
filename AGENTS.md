# Repository guidance

This is a new independent Sleeper-only model. Follow MODEL.md, including the owner’s ESPN fetch-timestamp override, the prospective v1.20 residual-defense update and the v1.21 shrinkage and reporting update. Do not edit any other repository. Keep raw scoring, fixed controls, stages, provenance and all accepted records immutable. Never add an external scoring feature or retroactively change a threshold. All methodology changes are prospective and versioned. From v1.22 only the moneyline creates selections (`selection_markets`); spread and total quotes are stored as context. The public season record pools replayed earlier games with live results at render time (`season.py`) and must keep its parts listed; replay never writes a ledger record or trains a parameter.

Before changing logic, run the relevant fixture tests. Before publishing, run `ruff check src tests`, `ruff format --check src tests`, `pytest -q`, `python -m sleeper_nba validate`, and `python -m sleeper_nba build-site`. Tests must not depend on live APIs. Browser smoke tests are optional after UI changes and use a locally served generated site. Do not put synthetic fixtures in the native transaction ledger.

The authoritative data is data/transactions. Preserve accepted forecasts on rendering failures; derived exports may be regenerated. Never print tokens or credentials. ESPN odds require no external API secret.

The owner authorized incorporating residual defense with 25-calendar-day decay and testing shrinkage on last season. The scoring component is defense-only with a 20-game offensive nuisance control. v1.20 used a 5-game defensive prior; the owner-requested v1.21 review raised it to 40 (see MODEL.md and `research/defense_prior_replay.py`). Each methodology version keeps its own team-residual and confidence histories, and public pages show the current version only, with small samples labeled exploratory. First-stage parameter history includes the explicitly labeled, hash-pinned 117-game legacy-first seed; locks never borrow it. Preserve raw/fixed forecasts and v1.19/v1.20 histories. Probability calibration starts a separate history for each version and uses frozen corrected targets, with no extra scalar scoring biases. New locks use the 15-minute window after T−5h (`five_hours_15min_v2`); forecasts frozen under the v1.20.1 through-tip policy keep it. Capture runs from the self-chaining `watch.yml` job with `watchdog.yml` as its restart; do not add a second writer or a cron that shares the writer concurrency group. Latest previews are untracked and must never create bets, grades or training observations.

The owner froze v1.22 settings and registered subsequent live evaluation from 2026-11-10T20:21:22Z in evaluation_plan.json. Keep its configuration/hash and start time fixed. Registered daily fitting continues. Settings changes require a new prospective methodology version. Performance leads with live-only, stage-specific paired log-loss/Brier comparisons against raw Sleeper and contemporaneous no-vig moneylines, with whole-slate bootstrap intervals. The pooled record is retrospective research, regardless of sample size.
